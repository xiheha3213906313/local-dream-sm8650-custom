# 小米 14（SM8650／12 GB）FP8 实验版

这份修改保留 Klein 4B 的 E4M3 权重，在 Hexagon v75 上按块转换为 FP16，再交给 HMX 计算。它不增加原生 FP8 指令支持，也没有把模型转成 Q4。

## 状态与边界

- 基线：Local Dream `2f1f3ba186eeca2a52268540108b3ee6e2296d17`，sd.cpp `854c9d1019775a3565c819362ac2dec29675911e`，ggml `f070ebe20c282c898681203228ae861114497d4b`。
- 已验证：主机端全部 256 个 FP8 编码、tile 排列、分块空间预算；Android 引擎和 v75/v79/v81/v85 DSP 库交叉编译。
- 未验证：小米 14 DSP 实际执行、完整出图、FastRPC 映射容量、12 GB 内存峰值和速度。内置诊断成功也不等于完整模型通过。
- 首版只开放 Klein 4B（支持内置下载及本地组件导入），512×512、4 步、单张文生图。使用原下载包、`all=disk`、关闭参数预取、强制 64×64 VAE tile（重叠 0.25）、4 个主机线程。
- DSP 虚拟驻留预算设为 3072 MiB；它不代表设备有同等可用物理内存。映射失败不会被假定为某个固定单缓冲大小上限。
- Qwen Image 2.1、其他模型、编辑和更高分辨率保持关闭，等待 Klein 真机验收之后的第二阶段。

## 本地导入

DiT 标签页新增“导入 DiT 模型”。选择配套的扩散模型、文本编码器、VAE 和 tokenizer，应用自动命名和归类；支持取消并保留已有模型。SM8650 仅接受检查通过的 Klein 4B FP8 扩散权重。详见[四个下载直链及操作步骤](klein-downloads.md)。

## 手机测试

1. 安装文件名带 `sm8650-experimental` 的 APK。应用 ID 为 `io.github.xororz.localdream.sm8650`，使用测试签名，可与官方版并存。
2. 在实验版设置中点击「运行适配诊断」。不要同时运行官方版或其他 NPU 应用。保持页面打开；三分钟未结束将终止诊断。
3. 在自动弹出的日志窗口保存结果（[保存与找回日志](log-export.md)）。日志必须有 `FP8_DIAG PASS`，并核对普通／segmented、单行／多行和 3072 宽度矩阵的 NRMSE 都不超过 0.01。
4. 下载 DiT 列表中的 Klein 4B。先生成一张，再连续生成两张；中途还要测试取消并重新生成。
5. 返回模型列表后保存生成日志，连同三张图回传。描述是否有散热器、是否充电和系统版本，便于解释耗时。

诊断不自动下载多 GB 模型，不自动宣称设备支持，也不向外发送数据。失败日志包含错误阶段、RPC 申请大小、已映射／分配峰值、进程 RSS 峰值。无权限获取的系统 DMA 总量不做推算。`FP8_DIAG HMX` 是所选 DSP 路径记录；其后的计算错误仍以失败处理。

## 构建

需要 JDK 21、Android SDK API 37、Gradle wrapper、Android NDK r29，以及 Hexagon SDK 6.7.0.0（Tools 21.0.04）。SDK 可从项目说明中的 `ghcr.io/snapdragon-toolchain/arm64-android:v0.8` 工具链镜像取得。保持代理与 CA 验证启用。

```bash
git submodule update --init app/src/main/cpp/3rdparty/stable-diffusion.cpp
git -C app/src/main/cpp/3rdparty/stable-diffusion.cpp submodule update --init ggml
export ANDROID_NDK_ROOT=/path/to/android-ndk-r29
export HEXAGON_SDK_ROOT=/path/to/hexagon/6.7.0.0
bash app/src/main/cpp/dit/build.sh
```

CMake 按顺序应用原有 ggml 补丁与 `ggml-v75-fp8.patch`。主机和 DSP 共用内部兼容格式编号，文件 dtype 与 DitEngine ABI v5 不变；不要混用不同修改版本的主机引擎与 v75 skel。

对于首轮测试 APK，复用**锁定官方 alpha.7 basic APK** 的核心和 QNN 库，保留许可证，不复制旧 DiT 引擎。这样不需要重新编译依赖 QNN SDK 的其他后端：

```bash
curl -fL https://github.com/xororz/local-dream/releases/download/v3.0.0-alpha.7/LocalDream_armv8a_3.0.0-alpha.7.apk -o upstream-alpha7.apk
python3 tools/stage-upstream-runtime.py upstream-alpha7.apk
./gradlew :app:assembleBasicDebug :app:testBasicDebugUnitTest -Psm8650Compat=true
```

提取脚本校验完整 APK 的 SHA256。生成 APK 中的 DiT 引擎、v75 skel、诊断程序和应用代码均由本修改构建；其他后端核心及 QNN 库为固定官方二进制。现有 C ABI 允许这种组合。应用通过子进程环境变量选择实验配置，兼容旧核心；源码核心另外提供 `--dit_profile sm8650_fp8_compat`，但复用官方核心的 APK 不使用这项新参数。

如果需要核心也从源码重建，另安装项目要求的 QNN SDK 2.51.0.260929，初始化其余子模块，按原 `app/src/main/cpp/build.sh` 构建并替换核心。此路径需另行验证，不能把复用二进制的构建结果当成核心源码构建通过。

不带 `-Psm8650Compat=true` 的构建不开放 SM8650 实验入口，保留原有 SM8750+ 判定和原生 FP8 计算路径。

## 开发验证与诊断

主机测试在应用补丁后的 ggml 上运行：

```bash
g++ -std=c++17 -O2 -Wall -Wextra -Werror -D__fp16=_Float16 \
  -Iapp/src/main/cpp/3rdparty/stable-diffusion.cpp/ggml/src/ggml-hexagon/htp \
  app/src/main/cpp/dit/tests/fp8_compat_test.cpp -o /tmp/fp8-compat-test
/tmp/fp8-compat-test
```

DSP 路径首次执行时还会穷举向量转换自检；失败直接返回错误。独立诊断构造 FP8 权重、FP32 激活、独立缩放与偏置，以同一 FP8 数据的标量解码作为 CPU 参考；比较全在手机上执行，不需要 ADB。

日志中的 `rss_peak_kib` 为进程峰值，`allocated_peak` 为当前进程跟踪的 RPC 分配峰值，`mapped_peak` 为成功映射峰值，不能将它们相加当作物理内存总占用。取消、失败和重复运行后应确认进程退出或资源回落。

Klein 真机验收后，再以同机 Q4_0 路径比较性能，随后才开放 Qwen Image 2.1 的独立 512×512／20 步验证。不能直接沿用 Klein 的内存或速度结论。
