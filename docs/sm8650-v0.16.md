# SM8650 v0.16：Qwen Image 2.1 分段加载

## 修复原因

小米 14 日志显示，Qwen Image 2.1 Turbo 已识别模型组件，文本编码器按 37 段完成计算，但主模型没有图切分标记，最终以 `segments=1 segmented=0` 整块准备权重。该段需要 6939.65 MiB，超过 HTP0 的 2048 MiB 托管预算，第一步采样前即失败。

## 修改

- 为 Qwen Image 2.1 主模型预处理增加切分边界，缓存时间条件、调制张量与联合 token 激活。
- 每个 Transformer 层增加独立边界，沿用现有分段权重管理与计算后释放流程。32 层模型可形成预处理、32 层与最终输出共 34 段；是否启用分段仍由内存规划器决定。
- 保持 HTP0 2 GiB 预算、磁盘按需加载与关闭预取，不通过提高预算来整块驻留主模型。
- 原始与 Turbo 权重共用该路径；参考图 token 布局和输出裁剪计算不变。
- 新增独立 `qwen21-segmentation.patch`，由 CMake 在现有 stable-diffusion.cpp 补丁之后应用，保留原子模块固定版本。
- 原生生成追踪标识更新为 `build=v0.16`，便于区分旧引擎日志。
