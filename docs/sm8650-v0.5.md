# SM8650 v0.5：数值范围保护与真实采样进度

v0.4 的手机反馈确认 12 组小信号矩阵诊断通过、27 段模型执行完成，但图像仍出现纯红或纯黑。流程完成不能视为正确出图。

## 修改

- 修正 v75 FP8 兼容路径的中间结果范围：未使用逐通道融合缩放时，HMX 写入临时 FP16 结果前乘以 1/256，读回 FP32 后再还原 256 倍。普通和 segmented 矩阵路径都处理；逐通道融合缩放及 v79+ 原生 FP8 路径保留原行为。权重文件与模型精度不变。
- 新增 4 组大幅值矩阵案例：相干求和会超过 FP16 的 65504 上限，小信号测试无法覆盖这一点。诊断现在共 16 组，仍以独立 CPU 参考及 NRMSE≤0.01 判定。
- 新增模型 runner 输出的 finite／NaN／Inf、最小值、最大值及 RMS 日志；发现非有限输出就中止生成，避免继续解码为无意义的图像。最终 RGB 也记录每通道范围与均值，用于区分计算问题与图像传输问题。
- 修复进度提前跳至 80%：权重加载的张量计数不再被当成采样步数。4 步采样按完成步数更新，VAE 解码结束后到 100%；加载期间不会伪造百分比。真实步数会写入 `FP8_DIAG sampling_step`。
- 沿用先前证书并启用 v1/v2/v3 签名，可覆盖安装。

## 验证与限制

主机回归演示了 6 个 FP16 中间结果溢出案例，采用保护缩放后可在 FP32 中精确还原；另运行 FP8 编码／tile／空间预算测试和生产 HVX 转换的 v75 模拟测试。

这验证了已发现的中间范围缺陷，不能证明它是手机纯色图的唯一原因。完整 HMX 矩阵、模型输出与手机安装仍需真机复测；新增日志不包含张量原始内容。

## 手机复测

1. 覆盖安装 v0.5，无需重新下载或导入模型。
2. 先运行适配诊断，确认全部 **16 组**比较通过、最后为 `FP8_DIAG PASS`。
3. 以 Klein 4B、512×512、4 步生成。四步之间进度会保持不动，这是实际步数进度；加载和第一步计算期间也可能较长时间停留在 0%。
4. 若生成失败或仍为纯色，请回传生成日志。`FP8_DIAG tensor` 可判断模型／VAE 输出数值，`FP8_DIAG rgb` 可判断图像在进入应用前的通道内容。不要把手机原始日志提交到公开仓库。
