# SM8650 v0.4：诊断计算与权重映射修复

## 修复内容

1. **FP8 转换自检失败**：v75 上原先使用的 qfloat 乘法使 14 个 FP8 非正规值的 FP16 编码增加 1 个最低位，导致逐位自检失败，矩阵计算返回 `INTERNAL-ERROR`。这个问题已在 Hexagon v75 模拟器复现。现在使用 HVX 整数运算构造这些编码，保留符号零和 NaN；生产代码和模拟测试共用同一转换、tile 重排实现，自检仍然启用。
2. **模型权重累计映射失败**：旧配置只设置算子批次的 3072 MiB VMEM，没有给模型规划器设置驻留预算。Hexagon 后端也不报告可用 VRAM，导致 Klein 以整图段准备权重。运行反馈显示累计映射约 3.9 GB 后，新增约 81 MiB 映射失败。实验配置现设置 `HTP0=2.0` GiB 的模型权重与图缓冲预算，开启自动分段并保持预取关闭，为 FastRPC 等分配留出余量。这不代表已测得某个固定驱动容量上限。
3. 诊断增加 3072、9216、12288 宽度的流水计算案例，并在开始每个案例前记录尺寸。出图日志新增实际分段数量、预算和预取状态。

FP8 权重文件、文件导入方式和已有模型目录保持兼容。权重仍以 FP8 储存，v75 仍按 tile 转换后使用 FP16 HMX 计算。原生 FP8 指令没有变化。

## 手机验证

直接覆盖安装 v0.4，**无需重新下载或导入模型**。

1. 设置 → **运行适配诊断**。新日志应有 12 组 `FP8_DIAG matmul`，每组 NRMSE 不超过 0.01，最后为 `FP8_DIAG PASS`。
2. 诊断通过后，用 Klein 4B、512×512、4 步先生成一张。日志应有 `managed_budget_mib=2048` 和 `runner=flux ... segmented=1`；实际分段数由图规划器决定。
3. 保存并回传新的诊断和生成日志。若仍失败，完整日志会包含案例尺寸、分段数和映射峰值。请通过对话发送，手机原始日志不需要公开上传到 GitHub。
4. 首张成功后再验证取消、重新生成及连续生成。诊断通过不等于完整模型出图已通过。

## 开发回归验证

主机测试覆盖 256 个编码、tile 布局以及有界的串行／流水 VTCM 规划，方法见 [构建与测试](sm8650-fp8.md)。下面的模拟测试直接调用生产 HVX 转换及 tile 重排代码：

```bash
HTP=app/src/main/cpp/3rdparty/stable-diffusion.cpp/ggml/src/ggml-hexagon/htp
"$HEXAGON_TOOLS_ROOT/Tools/bin/hexagon-clang" -mv75 -mhvx -mhvx-length=128B -G0 -O3 \
  -I"$HTP" app/src/main/cpp/dit/tests/fp8_hvx_test.c -o /tmp/fp8-hvx-test.elf
"$HEXAGON_TOOLS_ROOT/Tools/bin/hexagon-sim" -mv75 /tmp/fp8-hvx-test.elf
```

期望输出 `FP8_HVX_PASS errors=0`。测试覆盖全部 256 个编码、8 种排列、3 个相邻 tile 及边界保护值。注意模拟器进程的退出码可能不等于被模拟程序的返回值，应同时核对 PASS 输出和错误数量。

以上能够验证转换缺陷已消除；手机的驱动映射行为和完整出图仍需真机验证。
