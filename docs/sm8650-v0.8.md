# SM8650 v0.8：CPU / DSP VAE 解码开关

## 实机诊断结果

v0.7 报告中 `matrixExitCode=0`、`normExitCode=0`、`convExitCode=0`，16 组矩阵、8 组归一化、7 组卷积均通过。F16 affine+SiLU 的最大归一化误差约 0.269%，低于 1% 判定阈值；没有非有限输出。这验证了 GroupNorm 修复在小米 14 的真实 DMA／worker 路径上有效，完整模型解码仍需实际出图验证。

## 设置位置和行为

主页右上角「⋮ → 设置 → 功能设置 → CPU 解码」。此开关只在 SM8650 实验适配设备显示。

- **开启：CPU VAE**，保持 v0.6 起已正常出图的解码路径，关闭 direct-conv，不分块。
- **关闭：DSP VAE（HTP0）**，使用已修复 GroupNorm 的 direct-conv 路径，恢复 64 的 VAE 分块设置以控制 DSP 图的内存。
- 两种模式的 DiT 采样和文本编码器均使用 HTP0，FP8 权重无需重下。
- 选择自动保存，下次进入模型时生效。解码选择被纳入后端配置比较，即使旧进程还在退出宽限期，也会因模式变化重新创建，避免复用错误后端。
- 当前默认开启 CPU 解码。完整 DSP 解码实机验证后，再将未设置用户的默认值改为 DSP；用户已经明确选择的值应继续保留。
- 生成日志同时记录服务选择和原生实际选择，例如 `vae_backend=HTP0`、`stage=generation_begin ... vae=HTP0 vae_direct=1 tiling=1`，VAE 解码开始处还会记录实际 runtime backend。适配诊断独立检查 DSP 算子，不受此开关控制。

## 对照测试

1. 覆盖安装，无需重下模型。
2. 在上述设置中关闭「CPU 解码」，返回模型列表后进入 Klein。
3. 固定同一提示词、512×512、4 步、CFG=1、seed=42 生成，保存图片和生成日志。
4. 返回列表，再开启「CPU 解码」，使用完全相同参数生成并保存日志，用于比较画面和解码耗时。DSP 与 CPU 不要求逐像素相同。
5. 若 DSP 出图异常，开启开关并重新进入模型即可回到已验证 CPU 路径；保留异常生成日志用于继续定位。

本版本提供完整 DSP 解码的手动试用，不把算子自检通过等同于完整模型验证。没有连接手机的构建环境只能检查编译、打包与代码行为，最终 DSP 出图和耗时以手机日志为准。
