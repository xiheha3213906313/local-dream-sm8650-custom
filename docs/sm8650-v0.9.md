# SM8650 v0.9：解除当前 Klein 4B 的生成功能测试限制

## 恢复的功能

- 宽、高分别可调，使用项目现有 DiT 范围：512–2048，每次 64 像素，可生成非正方形图片。
- 步数可调：1–50。默认 4 步仍是 Klein 4B 的模型默认值，不再强制回到 4 步。
- 连续生成数量：1–10，沿用项目逐张生成方式，不一次在内存中并行创建全部图片。
- 恢复图生图、蒙版输入及 Klein 原生参考图编辑。仍尊重主页设置中的 img2img 用户开关；恢复后使用原有图像和参考图入口。
- 不再覆盖已保存的尺寸、比例、步数和张数；移除“512×512、4 步、单张文生图”的限制提示。
- 生成日志捕获遵循“设置 → 日志记录”开关，不再强制捕获。内部数值保护和私有阶段追踪保留，诊断入口仍可使用。

范围是当前已适配的 Klein 4B FP8 模型在项目中已有的生成与编辑功能。Qwen、Klein 9B、其他权重精度的模型适配不包含在这次功能解锁内。

## DSP 默认与兼容配置

此前的小米 14 日志已确认完整 DSP VAE 返回图片，数值没有异常，512×512 解码约 1 秒。现在未设置用户默认使用 DSP。主页「⋮ → 设置 → 功能设置 → CPU 解码」继续保留；已经明确选择 CPU 的用户保持原选择，不在升级时覆盖。

兼容配置改用 `LOCAL_DREAM_SM8650_PROFILE`，不再向核心服务传递旧的 `LOCAL_DREAM_DIT_PROFILE`。旧标记还会激活核心中的首轮验证入口，只解除界面和引擎检查不能解除该入口。新版将 SM8650 的 FP8 兼容、2 GiB 参数分段预算、无预取、进度路由与数值追踪保留在新标记下，与旧固定尺寸测试模式分离。核心服务公开 ABI 没有变化，沿用现有核心二进制。

DSP 继续使用分块 VAE；CPU 保留已验证的 512px 单帧解码，大于 512×512 的画布也启用分块，以控制工作内存。VAE 编码和解码使用同一后端选择。

## 验证与手机使用

- 新增主机接口回归测试：链接实际 `DitEngine.cpp` 与模拟 SD 运行层，通过公开 ABI 验证 10 个请求，覆盖非正方形、1024px、可变步数、图生图、蒙版、参考图、DSP 默认和 CPU 回退。测试断言参数传递、进度以及保留的内存预算；模拟层不执行模型数学计算。
- 更新并运行阶段追踪测试，验证新兼容标记仍启用诊断；补丁可逆应用检查、构建、项目单元测试与代码检查随版本执行。
- 覆盖安装，无需重下模型。在高级设置中调整尺寸、步数和张数；图像编辑使用恢复的原有入口。无需再做 CPU 对照测试。

512px 文生图和 DSP 单算子已有实机证据；更大画布、更多步数、连续多张及编辑功能仍需实机使用验证。解锁配置范围不等于已验证 2048px 在 12 GB 设备上的内存和速度表现。
