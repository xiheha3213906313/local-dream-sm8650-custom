# 诊断日志保存修复（v0.3）

本版本修复设置页中日志“保存”缺少可见反馈的问题。旧版的提示显示在被设置页遮住的界面上，并且等待提示结束后才关闭日志窗口。

## 操作方法

1. 覆盖安装 v0.3，保留应用数据与已经导入的模型。
2. 设置 → **查看上次诊断日志**。应用会优先打开最近的诊断记录，也能读取 v0.2 留在应用缓存中的原始诊断输出。如果系统已经清除了缓存，需要重新运行适配诊断。
3. 点击 **保存**，在系统文件窗口中选择位置并确认。返回后，日志窗口显示“日志已保存到所选位置”。文件为 UTF-8 文本，默认名称为 `local_dream_log_时间.txt`。
4. 也可以点击 **复制全文**；成功或失败都在当前窗口提示。特别长的日志可能超过系统剪贴板限制，请使用保存功能。
5. 保存、复制或取消系统文件窗口均保留当前日志。点击“关闭”才收起日志窗口。新诊断报告另存于应用私有目录，方便下次查看。

旧版可能已经将文件写入手机的 **下载/LocalDream**，文件名以 `local_dream_log_` 开头、以 `.log` 结尾。可先通过文件管理器查看。

## 回归检查

- 从设置页打开日志并保存：系统选择位置；保存后在当前窗口显示结果，文本应与完整日志一致。
- 取消文件窗口：显示取消信息，日志保留，可重新保存。
- 目标不可写或未安装文件选择器：显示错误，不丢失当前日志。
- 复制全文：成功提示在当前窗口显示；复制失败提示使用保存功能。
- 关闭并重新启动应用：通过“查看上次诊断日志”重新打开记录。
- v0.2 覆盖升级：未被系统清理的诊断缓存可直接恢复，无需先再次运行诊断。

APK 构建、现有单元测试及代码格式检查在开发环境执行。系统文件选择器与剪贴板交互仍需在手机上验证。

此版本未修改 DSP 内核。已收到的手机截图显示 `HTP0 synchronize failed: dsp-error INTERNAL-ERROR`；需要完整诊断日志进一步定位。请通过对话回传日志，不必将手机日志提交到公开 GitHub 仓库。
